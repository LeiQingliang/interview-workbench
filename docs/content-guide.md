# 内容编写指南

练习内容的目标是帮助使用者形成真实、清楚、可核对的回答，而不是替使用者编造经历。

## 四种内容要分清

| 类型     | 写法                                         |
| -------- | -------------------------------------------- |
| 事实说明 | 给出来源与适用范围；时效性内容标明核对时间   |
| 练习建议 | 使用“可以”“建议”“可按实际情况调整”等表述     |
| 虚构情景 | 在情景旁明确写“虚构练习假设”，包括数字与结果 |
| 本人填写 | 用问题或占位提示引导，不预填具体业绩与故事   |

不要把示范中的第一人称陈述默认为使用者的真实意愿。动机、城市偏好、工作强度与到岗条件，应由使用者自己确认。

## 数据和成果

- 写清时间、范围、分子、分母与数据来源。
- 区分个人动作、团队结果和组织资源。
- 区分订单、人数、收入、到账、利润和GMV等不同指标。
- 区分锁单、付款、交付和复购等不同状态。
- 不把相关性写成已验证的因果关系。
- 不把工程测试条数写成准确率或商业成效。
- 未核实的口径使用待填写项，不为让案例完整而倒推出数字。

涉及算题时，应独立复算，并披露费用、退款、观察周期与比较基线。训练数值不得伪装成平台费率、行业基准或个人成绩。

## 问答写法

一道问题应集中考察一项主要能力。建议包含：

1. 题目与考察点。
2. 可调整的回答框架。
3. 一到两个追问。
4. 需要使用者补齐的事实。
5. 有助于避免误解的边界说明。

优先采用具体、简短的业务语言。专业术语应解释用途，不以术语数量代替实际动作。行为题允许使用失败或尚未解决的问题，不要求每个故事都以成功收尾。

## 内容结构与HTML

内容保存在 `content/guide.json`，字段应遵循仓库现有结构与检查脚本。为章节、问题及笔记区域保留唯一且稳定的标识；文本重写通常不应改变笔记关联。

存放HTML的字段（例如 `sourceHTML`）只接受受信任作者编写、评审过的内容。不要加入脚本、内联事件处理、第三方追踪、未知嵌入页面或任意上传入口。普通填写内容应作为文本处理，不解释为HTML。

使用有语义的标题、列表和表格。每个输入区域提供可关联的label；链接文字应说明目标。避免只靠颜色区分重要状态，也不要让长表格在窄屏上遮挡操作。

## 引用与许可

尽量引用原始、权威来源，提供机构或作者、材料标题和直接链接。时效性岗位要求与规则应注明适用范围，不能从一个岗位推导整个公司的固定筛选规则。

原创内容适用项目MIT许可。第三方引用、图片和商标保留各自权利，必须核对允许的使用方式并标明归属。不复制大段招聘材料、文章或商业题库，也不假称与相关品牌存在合作。

## 发布前检查

- 所有样例是否通用、匿名，并明确假设性质？
- 是否意外包含姓名、电话、邮箱、真实客户或原始订单信息？
- 每个数字是否能按给定假设复算？
- 动机和经历是否留给使用者确认？
- 是否错误宣称官方题库、内部评分标准或保证录用？
- 内容和字段标识是否唯一，现有笔记是否仍能对应？
- 是否完成检查、构建与实际页面阅读？

先用内容检查发现结构问题，再以使用者视角阅读全文。自动检查不能替代事实、许可与语义审查。
